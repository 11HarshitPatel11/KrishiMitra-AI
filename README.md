## 1. Project Overview

**KrishiMitra AI** is a comprehensive agricultural decision-support platform designed to assist farmers, agricultural students, and extension officers. The platform combines agronomic data modeling, machine learning, and external environmental intelligence to deliver:
1. **Soil- and Climate-Aware Crop Recommendations:** Evaluates environmental and soil characteristics (N, P, K, pH, temperature, humidity, and rainfall) using a trained Random Forest model, augmented by mandi market price intelligence and crop rotation history.
2. **Plant Disease Identification & Actionable Guidance:** Identifies 38 distinct crop disease/healthy states from uploaded leaf photographs using a MobileNetV3 deep learning model, linked with 26 university-extension-verified disease management and prevention profiles.
3. **Multi-Farm Profile & Soil Tracking:** Allows farmers to manage multiple agricultural holdings with coordinates, historic cropping records, and SoilGrids v2.0 global soil data.

> [!IMPORTANT]
> **Advisory Limitation Notice:** Recommendations and disease predictions generated by KrishiMitra AI are advisory outputs derived from statistical models and reference datasets. They do not constitute guaranteed agricultural yields or professional pesticide prescriptions. Always consult your local agricultural extension service (e.g., KVKs in India) before applying chemical treatments.

## 2. Architecture Overview

KrishiMitra AI follows a clean, decoupled three-tier microservice architecture:

```text
┌─────────────────────────┐
│  React / Vite Frontend  │  (Port 3000 / SPA)
└────────────┬────────────┘
             │ HTTP / REST (Bearer JWT)
             ▼
┌─────────────────────────┐      Mongoose      ┌──────────────────┐
│ Node.js / Express API   │ ─────────────────► │ MongoDB Database │
│     (Port 5000)         │                    └──────────────────┘
└────────────┬────────────┘
             │ Internal REST (Server-to-Server)
             ▼
┌─────────────────────────┐
│ Python / FastAPI ML     │  (Port 8000 / Internal Microservice)
│ (RandomForest + PyTorch)│
└─────────────────────────┘
```

1. **Frontend (`client/`):** Responsive Single-Page Application (SPA) built with React 18, Vite, React Router v7, and Tailwind CSS.
2. **Backend API Gateway (`server/`):** Express.js server providing authentication, input validation, multi-tenant farm isolation, rate limiting, external API integrations, and database persistence with MongoDB.
3. **ML Microservice (`ml-service/`):** Python FastAPI service hosting serialized scikit-learn and PyTorch neural network artifacts for high-performance inference.
4. **Database:** MongoDB document store managing users, farms, crop history, soil profiles, and disease management knowledge bases.

## 4. Implemented Modules & Capabilities

### 4.1 Authentication & User Profile Management
* Secure registration and login with `bcryptjs` password hashing (salt rounds: 10).
* Stateless JWT authentication with Bearer token header verification.
* Built-in in-memory rate limiting on `/api/v1/auth/register` and `/api/v1/auth/login` (10 requests per 15-minute sliding window) returning HTTP 429 and `Retry-After` headers.
* Authenticated profile endpoints: `GET /api/v1/auth/me` and `PATCH /api/v1/auth/profile` with strict payload whitelisting (`name`, `mobileNumber`, `location`).

### 4.2 Multi-Farm & Crop History Management
* Full CRUD operations on user-owned farm profiles (`/api/v1/farms`).
* User-scoped MongoDB index on `Farm.userId` (`{ userId: 1 }`) to eliminate unindexed collection scans.
* Strict multi-tenant isolation guaranteeing users can only read, update, or delete their own holdings.
* Cascading dependency protection: Deletion of a farm is blocked (HTTP 409 Conflict) if related `CropHistory`, `SoilInformation`, or `ExternalSoil` records exist.
* Historic crop recording per farm (`/api/v1/crop-history`) used to avoid recommending repeat crops (crop rotation awareness).

### 4.3 Crop Recommendation Engine
* Evaluates 7 canonical features: Nitrogen (N), Phosphorus (P), Potassium (K), Temperature (°C), Humidity (%), pH, and Rainfall (mm).
* Integrates market profitability weighting using real-time Mandi price data.
* Location-aware: Resolves state and district via reverse-geocoding from farm coordinates, with manual state/district fallback support when coordinates are absent.
* Pure ML Contract: Location data is used strictly for market pricing in the Node.js backend; exactly 7 features are forwarded to the FastAPI service.

### 4.4 Plant Disease Detection & Verified Guidance
* Convolutional neural network based on MobileNetV3 Small architecture, trained across 38 PlantVillage leaf disease and healthy control classes.
* Confidence thresholding: Predictions with confidence < 70% are flagged as `uncertain`, and treatment guidance is safely withheld to avoid inappropriate chemical interventions.
* Knowledge Base: 26 curated, extension-verified disease profiles containing symptoms, causes, cultural prevention, and IPM management strategies (with citations to agricultural university extension bulletins).

### 4.5 Soil Information & ISRIC SoilGrids Integration
* Automated retrieval of global raster soil data from ISRIC SoilGrids v2.0 based on farm latitude and longitude.
* Depth interval preservation (0–5 cm, 5–15 cm, 15–30 cm, etc.) and automatic unit conversion (pH × 10 to standard pH, cg/kg to g/kg).
* Safe fallback handling for oceanic or unmapped coordinate pixels.

### 4.6 Weather Integration & Rainfall Transparency
* Automated temperature and humidity retrieval via Open-Meteo REST API based on coordinates.
* **Rainfall Input Guidance:** The system provides transparent UI guidance explaining that the rainfall accumulation period in the underlying training dataset is unconfirmed in academic literature. Instantaneous weather precipitation is **not** silently substituted; farmers are guided to input realistic seasonal/annual rainfall values.

### 4.7 Mandi Market Commodity Intelligence
* Integration with India Data.gov.in Mandi prices API.
* Commodity canonicalization supporting over 40 common regional aliases (e.g., "Paddy (Dhan) (Common)" -> "rice", "Arhar (Tur/Red Gram)(Whole)" -> "pigeonpeas", "Gram (Chana)" -> "chickpea").
* Safe fallback: Unmapped commodities safely return `null` to avoid false recommendations.

## 5. Environment Configuration

Each subsystem requires environment configuration before starting. **Never commit `.env` files or secrets to version control.**

### 5.1 Backend (`server/.env`)
Copy `server/.env.example` to `server/.env`:
```bash
cp server/.env.example server/.env
```
Key configuration items:
* `PORT`: Backend port (default: `5000`).
* `NODE_ENV`: `development` or `production`.
* `MONGODB_URI`: MongoDB connection string (e.g., `mongodb://localhost:27017/crop_recommendation`).
* `JWT_SECRET`: Secure random secret for JWT signing (minimum 8 characters).
* `ML_SERVICE_URL`: URL of the FastAPI microservice (e.g., `http://localhost:8000`).
* `ALLOWED_ORIGINS`: Comma-separated CORS allowed browser origins (e.g., `http://localhost:3000`).
* `WEATHER_API_BASE_URL`: Open-Meteo endpoint (default: `https://api.open-meteo.com/v1/forecast`).
* `MARKET_API_BASE_URL`: Data.gov.in endpoint.
* `MARKET_API_KEY`: API key for Data.gov.in.
* `AUTH_RATE_LIMIT_WINDOW_MS`: Rate limit window in ms (default: `900000` = 15m).
* `AUTH_RATE_LIMIT_MAX`: Max auth attempts per window per IP (default: `10`).

### 5.2 Frontend (`client/.env`)
Copy `client/.env.example` to `client/.env`:
```bash
cp client/.env.example client/.env
```
Key configuration item:
* `VITE_API_URL`: Backend API base URL (default: `http://localhost:5000/api/v1`).
> [!WARNING]
> Any variable prefixed with `VITE_` is bundled into client-side JavaScript and is publicly readable in the browser. Do not store database credentials, private keys, or API secrets here.

### 5.3 ML Service (`ml-service/.env`)
Copy `ml-service/.env.example` to `ml-service/.env`:
```bash
cp ml-service/.env.example ml-service/.env
```
Key configuration items:
* `PORT`: ML service port (default: `8000`).
* `ENVIRONMENT`: `development` or `production`.
* `ML_ALLOWED_ORIGINS`: Comma-separated CORS allowed browser origins. Defaults to empty list in production (strict server-to-server isolation). Wildcards (`*`) are strictly prohibited.

## 6. Installation & Local Development

### Prerequisites
* **Node.js:** v18.0.0 or higher
* **Python:** v3.10 to v3.13
* **MongoDB:** v6.0+ (running locally or via MongoDB Atlas connection string)

### 6.1 Running the Backend (Node.js/Express)
```bash
cd server
npm install
npm start
```
* Health check: `GET http://localhost:5000/api/v1/health`

### 6.2 Running the ML Microservice (Python/FastAPI)
```bash
cd ml-service
python -m venv venv

# On Windows:
venv\Scripts\activate
# On Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
* Health check: `GET http://localhost:8000/health`

### 6.3 Running the Frontend (React/Vite)
```bash
cd client
npm install
npm run dev
```
* Open your browser at `http://localhost:3000`

### 7.2 Production SPA Routing (Nginx / CloudFront / Apache)
The frontend utilizes React Router v7 HTML5 History API routing. When deploying to production web servers, direct navigation or page refresh on application routes (`/recommendation`, `/farms`, `/disease`, `/market`, etc.) will return **HTTP 404** unless an SPA fallback rewrite is configured.

A production-ready Nginx configuration template is provided at:
[`client/nginx.conf.example`](client/nginx.conf.example)

Key Nginx configuration snippet:
```nginx
# Static assets cached immutably with strict 404 on missing assets
location /assets/ {
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, immutable";
}

# SPA Application routes fallback to index.html
location / {
    try_files $uri $uri/ /index.html;
}

# Backend API reverse proxy (never rewritten to index.html)
location /api/ {
    proxy_pass http://localhost:5000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

## 9. Current Limitations & Known Considerations

1. **Rainfall Training Accumulation Period:** The academic dataset underlying the crop recommendation model does not document whether rainfall figures represent monthly, crop-cycle, or annual precipitation. Users must provide values aligned with their local agronomic knowledge.
2. **Third-Party API SLAs:** External integrations (Data.gov.in, Open-Meteo, SoilGrids, OpenStreetMap Nominatim) do not offer guaranteed enterprise SLAs. High-volume deployments should implement caching proxies.
3. **Clustered Rate Limiting:** The backend rate limiter operates in-memory per Node process. Multi-replica containerized deployments (Kubernetes, AWS ECS) should introduce a Redis-backed rate store.
4. **Production Database Indexing:** For existing production MongoDB deployments, verify or apply the `userId` index on the `farms` collection in the background:
   ```javascript
   db.farms.createIndex({ userId: 1 }, { background: true });
   ```
5. **Advisory Nature:** Always cross-reference machine learning recommendations with local agricultural extension offices before undertaking significant planting or spraying decisions.
